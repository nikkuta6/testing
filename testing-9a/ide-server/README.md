# Веб-IDE (Ace Editor)

HTTP-сервер на встроенном в JDK `HttpServer`, без зависимостей. Компилятор и VM
берутся из исходников `../Software testing` (сам проект не меняется).

```shell
mvn compile exec:java            # нужен JDK 25, как и для Software testing
```

Открыть http://localhost:8080/ , запуск — кнопка ▶ или Ctrl+Enter.
Пошаговый режим — 🐞 или F5: F10 шаг по строке, F11 по инструкции, Shift+F10 назад, Shift+F5 стоп.
Текущая строка подсвечивается жёлтым (в коде и в байт-коде), строка с ошибкой — красным. Переменные текущего вызова функции
показываются в окне «Локальные переменные», глобальные — в окне «Глобальные переменные».
A− / A+ меняют размер шрифта только в окне кода.

## Графика

Окно «Графика» в нижней панели отображает canvas. Его можно переставить за заголовок
и изменить ширину разделителями, как остальные окна. Кнопка «Пример» заменяет код
в редакторе примером рисования; нажмите ▶ для запуска. «Очистить» очищает изображение.

Графические команды — отдельные инструкции языка, без возвращаемого значения:

| Команда | Действие |
|---|---|
| `canvas(width, height);` | Задать размер в пикселях (целые 1–4096), очистить белым и сбросить цвет на чёрный |
| `color(r, g, b);` | Задать цвет контуров; каждый компонент — целое 0–255 |
| `line(x1, y1, x2, y2);` | Отрезок между двумя точками |
| `circle(x, y, radius);` | Контур окружности с указанным центром и неотрицательным радиусом |
| `rect(x, y, width, height);` | Контур прямоугольника от левого верхнего угла; размеры неотрицательные |
| `clear();` | Очистить холст белым, сохранив размер и цвет рисования |

Начало координат — слева сверху; X направлен вправо, Y вниз. Размер по умолчанию —
640 × 480, цвет — чёрный. Координаты могут быть дробными, аргументы могут содержать
выражения, переменные и вызовы функций. Команды работают в циклах и внутри `fun`.
Рисование обрезается по границам холста. Каждый запуск начинает с чистого холста;
при ошибке выполнения остаются уже выполненные команды. В пошаговом режиме рисунок
восстанавливается на выбранный шаг, в том числе при движении назад. Лимит — 10 000
графических команд за запуск. При тайм-ауте графика не возвращается.

```text
canvas(400, 240);
color(40, 110, 220);
rect(20, 20, 360, 200);
circle(200, 120, 70);
color(220, 60, 60);
line(20, 120, 380, 120);
```

## API

`POST /api/run`, тело — исходный текст программы.

Ответ при синтаксической ошибке:

```json
{"syntaxError": {"message": "...", "line": 2, "position": 9}}
```

Иначе:

```json
{"bytecode": "0000  PUSH 1.0\n...", "output": "...", "runtimeError": null,
 "variables": {"x": "2.5", "z": "3.0+4.0i", "a": "[1.0, 0.0-2.0i]"}, "locals": {}, "stack": []}
```

`variables` — глобальные переменные и массивы, `locals` — переменные и массивы текущего
вызова `fun` (на верхнем уровне пусто; при рекурсии — только самый внутренний кадр).
Значения — строки в формате VM: `2.0`, `3.0+4.0i`, `[1.0, 0.0-2.0i]`.
Ошибки выполнения (в том числе переполнение `int`) приходят текстом в `runtimeError`.

Поле `graphics` содержит команды рисования в порядке выполнения:
`[{"name":"line","arguments":[0.0,0.0,100.0,100.0]}]`.
В снимке каждого шага `/api/debug` поле `graphics` — количество уже выполненных
команд: для отображения берётся этот префикс итогового массива `graphics`.

`POST /api/debug` — то же самое плюс `"lines"` (строка исходника для каждой инструкции, 0 — нет)
и `"steps"`: снимок VM перед каждой инструкцией `{"pc": 3, "out": 0, "variables": {...}, "locals": {...}, "stack": [...]}`,
где `out` — длина уже напечатанного вывода. Записывается не больше 5000 шагов.

Программа выполняется не дольше 3 секунд, вывод ограничен 1 МБ.
